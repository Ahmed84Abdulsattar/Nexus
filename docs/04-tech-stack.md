# 04 · Tech stack

Use these choices. Do not add or replace a library that affects more than one module without an ADR. Small helper libraries inside a module are fine if they are maintained, MIT/Apache licensed and have no known vulnerabilities.

Versions: use the current stable major at project start and pin exact versions in `pnpm-lock.yaml`. Renovate proposes upgrades.

## Language and repo
| Area | Choice | Why |
|---|---|---|
| Language | **TypeScript 5.x**, `strict: true` everywhere | One language across frontend, backend and worker, so both developers can work on either side |
| Runtime | **Node.js 22 LTS** (move to the next LTS when it is active). `.nvmrc` and CI pin 22, so CI is the reference; `engines` is `>=22`, so a newer local Node (e.g. 24) is allowed | LTS support, native fetch |
| Package manager | **pnpm** workspaces | Fast; strict dependencies |
| Monorepo tasks | **Turborepo** | Cached `build/test/lint` per package |
| Lint / format | ESLint (flat config, typescript-eslint, import rules), Prettier | The same rules for everyone and every agent |
| Git hooks | Husky + lint-staged; Conventional Commits (commitlint, `config-conventional` with `subject-case` off so subjects can start with a backlog ID) | Clean history and changelogs |
| Dependency updates | Renovate | Security patches |

## Backend (`apps/api`, `apps/worker`)
| Area | Choice | Notes |
|---|---|---|
| Framework | **NestJS 11** with the **Fastify** adapter | Modules map to the architecture modules. Fastify is faster than Express. |
| Database access | **Kysely** (typed SQL builder) + `pg` pool; types generated by `kysely-codegen` from the live schema | Full control of SQL, partitions and jsonb. No heavy ORM magic. |
| Migrations | **Plain SQL files** in `db/migrations`, run by **node-pg-migrate** | The SQL in `db/schema.sql` is the reference. Every migration is reversible. |
| Validation | **zod** (via `nestjs-zod`); schemas shared in `packages/shared` | The same validation in web and API |
| API docs | `@nestjs/swagger` → OpenAPI 3.1 at `/docs` and `openapi.json` | The frontend client is generated from it |
| Auth | **jose** to validate Entra ID JWTs against the tenant JWKS | Issuer, audience, expiry and signature are checked |
| Scheduling | `@nestjs/schedule` in the worker; **Postgres advisory lock** for the single leader | No extra infrastructure |
| HTTP to DATOMS | Node `fetch` (undici) wrapped by `packages/datoms-client` with its own retry and budget logic | |
| Live push | `@azure/web-pubsub` (server SDK) | |
| Logging / telemetry | **pino** (`nestjs-pino`) + **OpenTelemetry** → Azure Monitor (`@azure/monitor-opentelemetry`) | Correlation IDs |
| Config | zod-validated env, `@azure/identity` + `@azure/keyvault-secrets` | The app fails fast if config is wrong |
| Tests | **Vitest** (SWC), supertest, **Testcontainers** (real Postgres in tests), **k6** for load | |

## Data
| Area | Choice | Notes |
|---|---|---|
| Database | **Azure Database for PostgreSQL Flexible Server 16** (zone-redundant HA in prod) | The same SQL runs on-premise PostgreSQL 16 |
| Time series | **Native PostgreSQL partitioning** (daily partitions for packets) + **Nexus rollup tables** (5 min / 1 h / 1 day) built by SQL functions **once per closed bucket** (no sliding window, no in-memory accumulators in phase 1) | See `adr/0003-database-time-series.md` and `adr/0007-sql-rollups-per-closed-bucket.md`. Azure allows only the Apache edition of TimescaleDB, which has no compression or continuous aggregates, so Nexus does not depend on TimescaleDB. |
| JSON | `jsonb` for parameter sets, with `lz4` column compression | DATOMS sends ~103 parameters per packet, so one row per packet keeps row counts 100× lower than one row per parameter |
| Cache | None in phase 1 (in-process LRU for auth and lookups). **Azure Cache for Redis** only when there are more than 3 API replicas or measured need. | |
| Files | Azure Blob Storage (phase 2) | |

## Environment variables (single list; `.env.example` must match it)
| Variable | Used by | Example / notes |
|---|---|---|
| `NODE_ENV` | all | `development` / `production` |
| `APP_ENV` | all | `local` / `dev` / `prod` (no `test` environment, ADR 0008) |
| `DATABASE_URL` | api | The API's own login (role `nexus_api`). Local: `postgres://nexus_api_local@localhost:5432/nexus`. Required, no fallback. The API needs a **direct** connection (port 5432, not PgBouncer 6432) because it also holds one `LISTEN` connection for access-cache invalidation. In Azure: host + Entra token through managed identity. |
| `WORKER_DATABASE_URL` | worker | The worker's own login (role `nexus_worker`). Local: `postgres://nexus_worker_local@localhost:5432/nexus`. **Falls back to `DATABASE_URL` only when `APP_ENV=local`.** In dev and prod it is required: a fallback would run the worker with the API's grants. |
| `DATABASE_ADMIN_URL` | `pnpm db:migrate`, `db:seed`, `db:check` (never a running app) | A login that can create roles, schemas and databases (locally the superuser: `postgres://nexus@localhost:5432/nexus`; in Azure the server admin, used only by the deployment pipeline). **Falls back to `DATABASE_URL` only when `APP_ENV=local`**; in dev and prod it is required, otherwise migrations would run as the API user. Migrations then run as the role `nexus_migrator`, which owns every table. |
| `DATABASE_POOL_MAX` | api, worker | `10` |
| `TEST_DATABASE_ADMIN_URL` | tests (`@nexus/db/testing`) | Administrator login of a throw-away server, e.g. `postgres://nexus@localhost:5432/postgres`. Each test file creates and drops its own database. When unset, the PostgreSQL integration tests are skipped with a warning. CI sets it for the `postgres:16` service. |
| `PG_DUMP` | `pnpm db:check` | Optional full path to `pg_dump` (PostgreSQL 16 client). Otherwise found through `NEXUS_PG_BIN`, the portable install of `scripts/pg-local.ps1`, then `PATH`. |
| `ENTRA_TENANT_ID` | api, web (`VITE_ENTRA_TENANT_ID`) | Innovo tenant GUID (public identifier, not a secret) |
| `ENTRA_API_CLIENT_ID` / `ENTRA_API_AUDIENCE` | api | `nexus-api` app id / `api://nexus-api` |
| `ENTRA_JWKS_URL` | api | Optional, and an override is accepted **only when `APP_ENV=local`**; elsewhere it must be unset or exactly the default. Default: `https://login.microsoftonline.com/<ENTRA_TENANT_ID>/discovery/v2.0/keys`. The API accepts both `ENTRA_API_AUDIENCE` and `ENTRA_API_CLIENT_ID` as the token `aud` (see Q29). |
| `VITE_ENTRA_API_SCOPE` | web | `api://nexus-api/access_as_user` (the scope MSAL requests; matches `ENTRA_API_AUDIENCE`) |
| `ENTRA_WEB_CLIENT_ID` | web (`VITE_ENTRA_WEB_CLIENT_ID`) | `nexus-web` app id |
| `AUTH_MODE` | api, web | `entra` (default). `dev` is allowed **only when `APP_ENV=local`**: it signs local test tokens for seeded users. The API refuses to start with `dev` anywhere else. |
| `CORS_ALLOWED_ORIGINS` | api | Comma-separated browser origins that may call the API, e.g. `https://nexus-dev.innovo.example`. Exact origins only: no `*`, no path, no trailing slash; `https` required unless `APP_ENV=local`. Unset: `http://localhost:5173` when `APP_ENV=local`, otherwise none (browsers are refused). Any other origin gets no CORS headers. |
| `RATE_LIMIT_USER_PER_MINUTE` | api | Requests per signed-in user (token `oid`) per minute. Default `600`. Over it: 429 problem+json with `Retry-After`. In memory, per API instance (`08` §6). |
| `RATE_LIMIT_IP_PER_MINUTE` | api | Flood guard per client address per minute, also for requests with bad tokens. Default `3000` (many users share an office address). |
| `BODY_LIMIT_BYTES` | api | Largest request body. Default `1048576` (1 MiB). Larger: 413 problem+json. |
| `TRUST_PROXY` | api | How the client address is read from `X-Forwarded-For`: unset/`false` (default, local) or a comma-separated list of the proxies' IP addresses or CIDRs. A hop count is refused (Fastify 5 treats a number as "trust nobody"), and so are `true` and `/0` (any client could pick its own address). It sets the IP in the sign-in audit row and the IP rate limit; unset behind Azure means every user shares the ingress address. The value for Azure Container Apps is an open question (raised in the S1-09 PR). |
| `KEY_VAULT_URI` | api, worker | `https://kv-nexus-dev.vault.azure.net/` (secrets below are read from here in Azure) |
| `DATOMS_BASE_URL` / `DATOMS_ORG_ID` / `DATOMS_TOKEN` | worker, CLI | `DATOMS_ORG_ID` = `20283` (Innovo's org; public). Token comes from Key Vault in Azure. | `DATOMS_LIVE` | worker, CLI | `false` = use fixtures (default locally) |
| `DATOMS_MONTHLY_CREDIT_ALLOWANCE` | worker | From the contract (Q5) |
| `WEB_PUBSUB_ENDPOINT` / `WEB_PUBSUB_HUB` | api, worker | `https://wps-nexus-dev.webpubsub.azure.com` / `nexus` |
| `LIVE_MODE` | api, worker, web | `pubsub` (default) or `poll`. Locally, `poll` turns off push and the web app refetches every 60 s. |
| `ARCGIS_API_KEY` | api (served via `/v1/config`) | Referrer-restricted; Key Vault in Azure. One key per environment. |
| `VITE_DEV_ARCGIS_API_KEY` | web, **local only** | Interim (S0-09) until `GET /v1/config` runs locally (S1-02). Read only by the MSW `/v1/config` mock in Vite dev mode, from the developer's git-ignored `.env`. Never set in CI or Azure: the web build fails if it is set. Remove after S1-02. |
| `APPLICATIONINSIGHTS_CONNECTION_STRING` | all | |
| `VITE_API_BASE_URL` | web | `http://localhost:3000/v1` |
| `LOG_LEVEL` | api, worker | `info` |

**Database logins.** The three URLs are three different database users, so a bug in one process cannot use another's rights (`db/roles.sql`, `06` §9). The passwordless local users `nexus_api_local` and `nexus_worker_local` are members of `nexus_api` / `nexus_worker` (the roles are NOLOGIN) and are created only when `APP_ENV=local` by `db/seeds/dev-login-roles.sql`. The URLs may hold a password in other environments, so they are never logged or printed; error messages name only the variable. **Outside `APP_ENV=local` all three must use TLS**: the URL needs `sslmode=verify-full` (preferred; Azure Database for PostgreSQL Flexible Server serves a certificate that chains to a public root in the system store) or `sslmode=require`, otherwise the process refuses to start. The API also refuses port 6432 (PgBouncer): it needs a direct connection for `LISTEN`. Typical local `.env` lines:
```
DATABASE_ADMIN_URL=postgres://nexus@localhost:5432/nexus
DATABASE_URL=postgres://nexus_api_local@localhost:5432/nexus
WORKER_DATABASE_URL=postgres://nexus_worker_local@localhost:5432/nexus
```
Order on a new machine: `pnpm db:migrate`, then `pnpm db:seed` (it creates the two local login users), then `pnpm dev`.

Local development: Postgres from docker-compose (or `scripts/pg-local.ps1` on Windows without Docker), `DATOMS_LIVE=false`, `LIVE_MODE=poll`, and either `AUTH_MODE=dev` or a real dev Entra app registration.

There is no Microsoft Graph secret: the `nexus-api` token carries only the groups assigned to the application, so the 200-group overage path is not used (ADR 0008, Q16). Poll scope and budget share per environment are **settings** (`poll.subset_external_ids`, `budget.max_share`) set by `db/seeds/`, not environment variables (ADR 0005).

## Not used (and why) — do not introduce
| Not used | Why |
|---|---|
| Kafka, RabbitMQ, Event Hubs | One poller, one source and one DATOMS endpoint for telemetry (ADR 0010). Add Azure Service Bus only if DATOMS streaming or webhooks arrive (ADR). |
| Microsoft Graph for group overage | Not needed with the "groups assigned to the application" claim (ADR 0008) |
| Microservices, Kubernetes (AKS) | Too much operations work for this team. Container Apps scales enough. |
| GraphQL | REST + OpenAPI is enough, simpler to secure per project, and the reporting app will read REST |
| Prisma / TypeORM | Weak support for partitioned tables, jsonb and raw time-series SQL. Kysely gives typed raw SQL. |
| MongoDB / NoSQL | Relational access rules and joins are central. jsonb covers the flexible parts. |
| Next.js / SSR | Internal SPA behind login. Static hosting is simpler. |
| Google Maps / Azure Maps | ArcGIS was chosen (`adr/0002-map-arcgis.md`) |
