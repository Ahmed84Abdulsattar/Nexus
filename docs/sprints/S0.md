## 1. Scope decision (confirmed by Ahmed, 2026-10-09)
This plan covers **DATOMS, Entra ID and ArcGIS** work, the repo and infrastructure plumbing that S0 puts in place for them, and the design tokens and base components (S0-06), kept in S0 by decision 5 (section 8).

- **Kept as plumbing:**
  - **S0-01 (repo skeleton):** every other task depends on it.
  - **S0-02 (Azure dev):** Key Vault holds the ArcGIS key and later the DATOMS token. Container Apps runs the worker, which is the only DATOMS caller, and the Entra-protected API.
  - **S0-03 and S0-07 (CI/CD):** these deploy the worker, API and web app. The dev web URL is the MSAL redirect URI and the ArcGIS key's referrer.
  - **S0-05 (web shell and router):** MSAL (S0-08) and `<MapView>` (S0-09) need a host app, and the map must be lazy-loaded per route (`09` §1).
- **Kept by decision:** S0-06 (design tokens and base components), owned by the frontend developer. The state and status colours are named in `docs/source/structure.md` and listed as tokens in `11`, so nothing about them is open.
- **No DATOMS calls in S0.** S0 builds no DATOMS client code, stores no DATOMS token and records no fixtures. Every environment runs with `DATOMS_LIVE=false`. The DATOMS client is S2-02, which needs Q21 and Q22. Those questions do not block S0. (Update 2026-10-12: S2-02 is unblocked by a provisional DATOMS test key, `07` §3.1; Q21 and Q22 are still needed for the site, status, location and alert mapping.)

Status key: **Not started** = no branch, commit or file in the repo. S0-01 was checked by Ahmed on 2026-10-09: there is no `S0-01-repo-skeleton` branch locally or on origin, and no commit mentions S0-01. Portal or Azure work done outside git (S0-02, S0-04, S0-09 key) has not been verified.

## 4. Task notes (design details and reviews)
Every PR goes through **qa** against its acceptance check and the `14` checklist. Rows marked "security-reviewer" also need that review and a human review (`14` definition of done, item 4).

- **S0-01** (security-reviewer: no). The backlog lists only four folders. `05` wins, so every app and package is created now (empty), and the lint boundaries can be tested from day 1 (ADR 0001 consequences: boundaries are enforced by lint). The `api` skeleton serves only `/health/live`. It is `@Public()` per `10`, so the S1-02 default-deny test passes without changes. The full guard comes in S1-02. The worker has no jobs and no DATOMS client. `ci.yml` starts here with lint, typecheck, test and build so branch protection can require it; S0-03 extends it. **Branch rules:** PR titles start with the backlog ID (`CLAUDE.md` rule 12). Commits follow Conventional Commits (commitlint, `04`). Merge with **merge commits** (as PR #1 did), not squash, so both rules hold. The Docker engine is not running yet on Ahmed's laptop (`GETTING-STARTED.md`, Pending). That doesn't block this acceptance check (no DB needed), but it blocks S1-01.
- **S0-02** (security-reviewer: yes). Size the dev resources from `12` §5. A smaller dev SKU is allowed; record the choice in `dev.bicepparam`. Set Postgres to allow `PG_TRGM` (needed by `db/schema.sql`), with Entra auth on and no open public IP range. Private endpoints are prod and S7-02 work. Storage is created only as the `13` hook: no containers, no archive job (ADR 0008, Q15). Do **not** add a DATOMS token. Dev runs on fixtures until Q7/Q10 and S2-02 (ADR 0005). Do **not** create `frontDoor` or `network` modules here (ADR 0008, Q20).
- **S0-03** (security-reviewer: yes). Migrations-before-rollout is added by S1-01, when there are migrations. Add contract tests, `db:check` and the OpenAPI diff to `ci.yml` when their tasks land (S1-01, S1-03, S2-02).
- **S0-04** (security-reviewer: yes). Create the five groups from `08` §1 for now. The final role list is Q17; changing it later only changes `access.group_role` data, not code. **Precision for the runbook:** the "groups assigned to the application" filter uses the assignments on the app the token is issued **for**, which is `nexus-api`. So assign the Nexus groups to the `nexus-api` enterprise app, and also to `nexus-web` if "assignment required" is set there. Confirm this with acceptance check 1, then write the exact setup into `08` §1 in this PR. Decode tokens locally only. **Never paste a token into chat, a PR or a log** (`CLAUDE.md` rule 10); put a screenshot of the claims, with the signature removed, in the PR. If Innovo IT answers "no" to Q16 (no P1, or the claim can't be used), stop: that needs a new ADR (ADR 0008).

- **S0-08** (security-reviewer: yes). Read only the public `VITE_ENTRA_*` values from `04`. Roles and navigation by role are S1-02 and S1-08. The UI never decides access; the API does (`08` §5).
- **S0-09** (security-reviewer: yes, it handles ArcGIS credentials). Pages import only from `components/map/`. Sample markers carry no real site names and live only in `apps/web/src/test/` (hard rule 3). The adapter reads colours through the token map and never hard-codes them (`09` §2). The state and status tokens come from S0-06. The **portfolio map is 2D only** in product (`09` §3). The 3-mode switch is shown here to prove the wrapper and is reused by the project page (S4-04, S4-05). Create the dev key with basemap and elevation privileges only. Rotate it every 90 days (`08` §6). The prod key is created in S7-05.
